# PRD — PureCode 插件产品需求文档

- **创建日期**：2026-09-07
- **修改日期**：2026-09-07

## 1. 概述

### 1.1 要解决的问题

开发者向版权局申请软件著作权时，需提交一份包含源代码的 Word 文档，且文档中的代码应当**去除全部注释**、仅保留代码本体。此外，当委托第三方代理机构提交申请时，开发者往往无法决定代码文件在材料中的排列先后顺序，导致核心代码可能被排在靠后位置。

### 1.2 核心价值

PureCode 提供一站式的「代码净化与编排导出」能力：

1. **去注释**：基于可扩展的语言注释规则，自动剥离源代码中的全部注释，且**绝不修改原文件**；
2. **可编排**：以文件树精细勾选参与导出的文件，并可在独立窗口中自由调整文件出现的先后顺序；
3. **一键导出**：生成标准 `.docx` Word 文档，直接可用于软著申请材料。

### 1.3 目标用户

需要准备软件著作权申请材料的个人开发者与小型团队。

## 2. 用户故事

- 作为一名准备申请软著的开发者，我希望选择一个项目目录后，插件自动识别其中所有的文件格式，让我先粗选要处理的文件类型，以便排除无关文件。
- 作为一名开发者，我希望以文件树的形式浏览项目结构，并逐文件/逐目录勾选哪些文件进入最终的 Word 文档，以便精确控制提交内容。
- 作为一名开发者，我希望有一个专门的窗口调整文件在文档中出现的先后顺序（例如把核心模块排在前面），以便代理机构拿到的材料符合我的编排意图。
- 作为一名开发者，我希望导出时选择保存位置，文档以 `{项目名称}_code.docx` 预填命名，以便快速归档。
- 作为一名使用小众语言的开发者，我希望能自行添加/修改语言的注释规则（单行注释符、块注释符、字符串界定符、文件扩展名），以便插件能处理框架未内置的语言。

## 3. 功能需求

| 编号 | 功能 | 描述 |
|------|------|------|
| F1 | 选择项目目录 | 顶部 Toolbar 提供「选择项目目录」动作，经系统原生目录对话框选择 |
| F2 | 文件类型粗选 | 选定目录后自动扫描全部文件，弹出对话框列出所有检测到的扩展名（含文件计数）与复选框，默认全选；该粗选仅在每次选择目录并分析时出现一次 |
| F3 | 原文件零修改 | 去注释处理完全在内存中进行，仅作用于导出文档，项目源文件不发生任何写入 |
| F4 | 文件层级树 | 使用 UIKit Tree 组件（复选框 + 父子三态联动）按文件层级展示粗选通过的文件 |
| F5 | 精细勾选 | 用户经 Tree 复选框精细决定哪些文件写入 Word |
| F6 | 导出 Word | 导出标准 `.docx` 文档；每次导出弹出保存对话框，预填文件名 `{项目名称}_code.docx` |
| F7 | 文件顺序调整 | 独立排序对话框：列表展示当前选中文件的导出顺序，支持拖拽、上移/下移、恢复默认排序；默认顺序为深度优先、每层按名称字母序 |
| F8 | 文档组织 | Word 中每个文件的代码前插入该文件的相对路径标题 |
| F9 | 语言规则管理 | 独立语言设置对话框：左列为「添加」按钮与语言列表，右列为所选语言的注释规则（单行注释符、块注释起止符、字符串界定符、文档字符串界定符）与文件扩展名表单；支持新增自定义语言、修改内置语言（保存为用户覆盖）、恢复内置默认、删除自定义语言；用户规则持久化 |
| F10 | 主界面布局 | 顶部 Toolbar；下方左右分栏——左侧 Tree（初始固定宽度，向左吸附），右侧为设置区与处理日志区 |
| F11 | 导出净化选项 | 设置区提供两个开关：「无匹配规则文件原样保留」（默认开启）与「移除空行」（默认开启，导出文档不保留任何空行）；内置 Python 规则默认剥离行首 docstring（`"""`/`'''`） |
| F12 | 导出进度反馈 | 设置区提供进度条（UIKit ProgressBar）：分两阶段推进——处理文件阶段按文件、生成 Word 文档阶段按文件块；成功完成置绿，失败标红；重新选择目录时归零；处理日志区同步输出逐文件记录 |

## 4. 非功能需求

### 4.1 性能

- 目录扫描、去注释与文档生成为耗时操作，必须经框架后台任务系统在工作线程执行，UI 线程不阻塞；
- 日志与进度反馈经 UI 线程封送实时刷新。

### 4.2 安全与数据保护

- **绝不修改用户项目源文件**（F3 为硬性安全要求）；
- 导出的 docx 由用户自行选择保存位置，插件不擅自写入项目目录；
- 插件不收集、不上传任何用户代码。

### 4.3 兼容性

- 遵循 InstructionX 插件规范（`AGENTS-for-PLUGIN-DEV.md`），仅依赖框架公开接口（PluginServices、DataProvider、BackgroundTaskManager、ILogger、ILocalizationFacade）；
- 第三方依赖仅 `python-docx`，经 `IXPlugin.json` dependencies 声明，由框架自动安装；
- 用户自定义语言规则持久化于框架 DataProvider（SQLite），卸载插件时可选随数据清除。

### 4.4 可用性与国际化

- 界面文案全部经框架 i18n 取词，提供中文（默认，全键覆盖）与英文语言包；
- 语言切换实时生效（连接框架 `language_changed` 信号重取词）；
- 主题自动跟随框架全局 UIKit 主题，插件不自建主题。

### 4.5 可扩展性

- 去注释能力完全由数据驱动的语言规则支撑，新增语言无需改动引擎代码；
- 导出器以适配器模式隔离 python-docx，未来可平滑扩展其他导出格式。

## 5. 插件类型判断

- **单插件仓库**：`custom_plugin/` 仓库根放置 `IXRepo.json`（`plugins` 数组仅列出一个插件子目录）；
- 插件目录名 / 插件 ID：`pure-code`（kebab-case）；
- 插件显示名称：`PureCode`；
- 初始版本：`alpha.0.1.0`（开发期自测）。

## 6. 描述文件清单

| 文件 | 位置 | 说明 |
|------|------|------|
| `IXRepo.json` | `custom_plugin/`（仓库根） | 插件仓库索引，`plugins` 仅含 `pure-code` 一项 |
| `IXPlugin.json` | `custom_plugin/pure-code/` | 插件描述文件：`id=pure-code`、`version=alpha.0.1.0`、`main=entrance.py`、`dependencies={"python-docx": ">=1.1.0"}`、name/description 采用多语言字典形式 |

## 7. 已知边界（v1 不覆盖）

- Python docstring 采用行首启发式剥离（`"""`/`'''` 出现在行首、前面仅有缩进时视为文档注释；内置规则默认开启，可在语言设置中调整）；代价是**行首裸表达式形式的三引号字符串会被一并剥离**（词法上无法与 docstring 区分），赋值/参数位置的多行字符串不受影响；
- 文件自定义顺序仅存于内存，重新选择目录后重置（持久化列为后续扩展点）；
- 不内置软著模板的页数/行数自动裁剪（如「前 60 页」），文档内容为用户勾选文件的全量代码。
